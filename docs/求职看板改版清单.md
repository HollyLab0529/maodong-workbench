## 0. 怎么用这份文档

**发车顺序（不可打乱）**

1. **B0 地基**：加字段（全部可空）+ 批量接口 + 迁移脚本。只动 `server/`、`scripts/`，前端不动，老版本继续能跑。
2. **B1 每日主线**：默认视图改成「今天 / 本包 / 跟进」，新增投递模式。前端大改，依赖 B0 的字段。
3. **B2 补齐闭环**：全量页漏斗修正、简历库、面试、时间线、首页口径、日历/待办联动、策略体检。
4. **B3 打磨**：移动端、性能、导入器、版本对比。

**发版纪律**（按既有约定）：字段和接口必须在正式发车前部署到线上；先做兼容性 DB 变更（新字段可空），接口向后兼容发布，最后才删旧逻辑。

**分支**：`workbench/` 在 `dev` 分支开发，部署走 `zsh workbench/deploy/deploy.sh`。

## 2. 数据模型变更

### 2.1 `job_apps` 新增字段（全部可空，向后兼容）

| 字段 | 类型 | 含义 | 谁写 |
|---|---|---|---|
| `city` | string | 城市枚举：`北京` / `天津` / `上海` / `其他` | 迁移 + 表单（从 `location` 提） |
| `city_multi` | string | `"1"` 表示 JD 写了多城市 | 迁移 |
| `company_type` | string | `大厂` / `中小厂` / `其他` | 迁移 + 表单 |
| `source` | string | 渠道：`BOSS直聊` / `官网` / `内推` / `牛客` / `其他` | 迁移（吃掉误用的 tier 值） |
| `batch_date` | string `YYYY-MM-DD` | 这一包的日期（老 `batch` 是自由文本，不可排序） | 迁移 + 新建默认值 |
| `next_action` | string | 下一步动作，如「催 HR」「等二面通知」 | 手动 / 投递模式 |
| `next_action_date` | string `YYYY-MM-DD` | 下一步该做的日期，用于「跟进」页排序 | 手动 |
| `status_changed_at` | string ISO | 上次状态变更时间（判断卡了多久） | 服务端 PATCH 自动写 |
| `rejected_at` | string ISO | 进入「已取消」的时间 | 服务端自动写 |
| `_migrated` | string | 迁移版本标记，如 `v2` | 迁移脚本 |

**不改的字段**：`company / position / jd_code / location / business / link / applied_date / plan_date / publish_date / tier / batch / resume_id / status / note`。老数据一行不删。

### 2.2 语义修正（不新增字段，改读写规则）

- `tier` **只允许** `冲刺` / `主力` / `保底` / 空。其它值在迁移时搬到 `source`。
- `applied_date` **只由「标记已投 / 投递模式 / 表单明确填写」写入**，不再随状态变更自动补今天。
- `resume_id` 统一存 **number**（现在 `job_apps` 里是字符串 `"23"`，`resumes` 里是 number）。
- `status` 允许自定义值（见 3.1），未知值**原样保留**，不再塌成「待投递」。

### 2.3 `settings` 新增两项

```jsonc
// key = job_policy
{
  "big_companies": ["字节跳动", "快手", "小红书", "百度", "腾讯", "阿里", "拼多多", "京东", "得物", "哔哩哔哩"],
  "big_company_max_per_day": 2,
  "cities": ["北京", "天津"],
  "blacklist": ["美团"],          // 红线：投递前二次确认
  "daily_target": 10              // 每包目标数，用于进度条
}

// key = job_statuses（原有，扩两个可选字段）
[{ "name": "待投递", "tone": "teal", "group": "todo", "short": "待" }, ...]
```

`group` 取值：`todo`（未投）/ `applied`（已投等消息）/ `progress`（流程中）/ `closed`（结束）。缺 `group` 时按默认 10 档的映射推断，老配置不用改也能跑。

### 2.4 迁移脚本 `scripts/migrate_jobs_v2.js`

```bash
node scripts/migrate_jobs_v2.js --dry-run   # 只打印将要改什么
node scripts/migrate_jobs_v2.js             # 真跑
```

逻辑（**幂等**，`_migrated === "v2"` 的行跳过）：

1. `city`：从 `location` 里按 `北京|天津|上海` 取第一个命中；出现 `/` 且多城 → `city_multi = "1"`；都没命中 → `其他`。
2. `company_type`：命中 `job_policy.big_companies` → `大厂`，否则 `中小厂`；`position` 含「实习」且 `company_type === 大厂` → 仍按大厂算（配额要拦）。
3. `source` / `tier`：`tier` 不在三档内 → `source = tier; tier = ""`；`tier` 为空且 `batch` 含 `BOSS` → `source = "BOSS直聊"`。
4. `batch_date`：`batch` 里能解析出 `YYYY-MM-DD` 就用；否则取 `created_at` 前 10 位。
5. `batch`：空则写 `包-${batch_date}`；已有值保留（不破坏「BOSS-2026-11-19」这类命名）。
6. `resume_id`：转 number，指向不存在的简历 → 置空并在报告里列出。
7. `applied_date`：**原样保留**，不猜、不清空。`status` 脏值按 `group` 映射就地归一（如 `终止` → `已取消`）。
8. 写 `_migrated = "v2"`，**不动 `updated_at`**（否则周报的「最近更新」全被污染）。
9. 结束时打印报告：改了 N 行、各字段变更数、悬空 `resume_id` 列表、`tier` 被搬到 `source` 的 6 条明细。

跑之前先 `cp data/db.json data/backups/db.before-v2.json`。

### 2.5 体检脚本 `scripts/check_jobs.js`（只读，随时可跑）

输出：字段完整率（`publish_date` / `plan_date` / `applied_date` / `link` / `resume_id`）、重复 `link`、同 `公司+岗位` 重复、悬空 `resume_id`、按包的投递进度、大厂/中小厂配比。以后每次跑包前跑一遍。

## 3. 服务端改动（B0）

### 3.1 `server/index.js` · `COLLECTIONS`

- `job_apps` 数组追加：`city, city_multi, company_type, source, batch_date, next_action, next_action_date, status_changed_at, rejected_at, _migrated`。
- `interviews` 追加：`status_sync`（`"1"` 表示保存时同步推进看板状态）。
- `resumes` 追加：`file_size`（字节，用于删除前提示 / 清理孤儿文件）。

### 3.2 新增批量接口

```
POST  /api/data/:coll/bulk    body: { rows: [...] }   → { rows: [...], count }
PATCH /api/data/:coll/bulk    body: { ids: [], patch: {} } → { count }
```

- 用 `tx()` 包住，**全成功或全失败**，不要 for 循环逐条。
- `POST /api/data/:coll/bulk` 单次上限 200 条；每条走与单条 POST 相同的字段白名单。
- 批量 PATCH 成功返回 `count`，前端据此提示「已更新 N 条」；失败返回哪条出错（`failed_ids`）。
- 同步给 `/api/v1/:coll/bulk`（开放 API 也走同一个 handler，助手灌数据能用）。

### 3.3 `PATCH /api/data/job_apps/:id` 自动维护时间戳

- 若 `status` 有变化 → 写 `status_changed_at = now`。
- 若新 `status` 的 `group === "closed"` → 写 `rejected_at = now`；从 closed 改回 → 清空 `rejected_at`。
- **不再**在这里补 `applied_date`（这条规则从前端 `pickStatus` 里挪走并删除）。

### 3.4 `job_events` 去重

`POST /api/data/job_events` 前查：同 `user_id + app_id + title` 且 `created_at` 在 3 秒内的记录存在 → 直接返回已存在那条（`deduped: true`），不再插入。
（现状：id 8 / 9 是同秒两条完全相同的链接事件。）

### 3.5 简历删除时清文件

`DELETE /api/data/resumes/:id` 成功后，若 `file_url` 以 `/uploads/` 开头，`fs.unlink` 对应文件（失败忽略，不阻断）。
另加 `scripts/clean_orphan_uploads.js`：扫 `data/uploads/` 里没被 `resumes.file_url` 引用的文件，列出来，`--delete` 才删。

### 3.6 链接解析接口

把现有 `/api/fetch-meta` 包一层 `POST /api/jobs/parse-link  { url }`，返回 `{ company, position, publish_date, location, link }`：
- `company`：从页面 title / og:site_name 猜；
- `publish_date`：从正文里匹配 `YYYY-MM-DD`、`MM-DD`、`发布于 X 天前`；
- 全部是**建议值**，前端只做预填，不自动保存。

`Board.jsx` 里删掉本地版本，改为 import。**`web/src/pages/jobs/Board.jsx` 的 `normStatus` / `stageOf` / `STATUS_SHORT` / `TIERS` 全部移走。**

### 4.2 视图重构：`web/src/pages/Jobs.jsx`

顶层从「看板 / 面试复盘 / 简历库 / Offer 对比」保持不变，但**「看板」内部**从「三视图 + 8 个筛选」重做成四个工作区（二级 tab，记住上次选择到 `localStorage`）：

| 工作区 | 回答的问题 | 内容 |
|---|---|---|
| **今天** | 我今天要做什么 | 今日待投（可勾选批量）+ 逾期（一键滚到今天）+ 今日已投（灰色 ✓） |
| **本包** | 这一包投到哪了 | 按 `batch` 分组的卡片，每包：进度 x/y、配比体检、整包进投递模式、整包标已投 |
| **跟进** | 投出去之后谁没理我 | 已投未回音（按已投天数排序）+ 有 `next_action_date` 的提醒 + 卡在某状态超 N 天的 |
| **全量** | 我总共有哪些 | 原来的漏斗 + 搜索 + 档位/批次/城市/公司类型筛选（漏斗在这里才成立） |

组件拆分：
- `web/src/pages/jobs/Board.jsx` → 变成容器：拿数据、分发、提供共享 `reload`。
- 新增 `web/src/pages/jobs/TodayView.jsx`、`PackageView.jsx`、`FollowUpView.jsx`、`AllView.jsx`。
- 新增 `web/src/pages/jobs/ApplyMode.jsx`（投递模式，见 4.4）。
- 现有 `Board.jsx` 里的表单弹窗 `JobForm` 抽成 `web/src/pages/jobs/JobForm.jsx`，四个视图共用。

### 4.3 新增记录默认值（修「加了但没出现」）

`JobForm` 新建时：

- `plan_date` 默认 **今天**（不再是 range 为 unscheduled 才填）；
- `batch_date` 默认今天，`batch` 默认 `包-YYYY-MM-DD`；
- `status` 默认 `待投递`；
- 保存成功后：把返回的 row 直接插进本地 `apps`（不整表重拉），若当前视图不包含这条，右上角 toast 带动作「查看 →」，点击切到对应工作区并高亮该行 3 秒。

### 4.4 投递模式 `ApplyMode.jsx`（新）

全屏一次只处理一个岗位，键盘 `J/K` 上下、`Enter` 标记已投、`Esc` 退出。卡片内容从上到下：

1. `公司 · 岗位`，城市 / 来源 / 档位 / 批次小字；
2. **大号投递链接按钮**（`a` 标签 `target=_blank`，整宽 44px 高），旁边「复制链接」；
3. **招呼语 / 自荐信复制块**：自动从 `note` 里识别 `【招呼语】`「【自荐信】」短句段落，抽出来单独渲染 + 一键复制（`navigator.clipboard`，失败回落 `execCommand`），整段 note 折叠在下面；
4. **简历版本**：显示 `resumeName` + 「打开文件」直链；
5. 底部两个主按钮：「投完了」（写 `applied_date = today` + `status` 推进到第一个 `applied` 组状态 + 自动跳下一条）、「跳过」。

入口：本包卡片上的「开始投这包」、今日视图的「开始投」、详情里的「进投递模式」。

### 4.5 时间与状态筛选解耦（修「点了漏斗时间就没了」）

- `range` 与 `stageFilter` **正交**，可同时生效：`filter(a) = matchRange(a) && matchStage(a)`。
- 时间卡高亮只看 `range`，不再被 `stageFilter` 影响（现在 `active` 里混了 `!stageFilter`）。
- 点漏斗**不清空** range；点时间卡**不清空** stage。
- 日历里「还有 N 家没排投递日期」点击 → 设 `range=unscheduled` **并** 把视图切到该范围内的列表（现在停留在日历视图，看不到东西）。

## 5. B2 · 补齐闭环

### 5.1 状态模型唯一真源（修「自定义状态塌成待投递」）

- `colors.js` 的 `useJobStatuses()` 返回值扩展为 `{ statuses, styleOf, groups, shortOf, byGroup }`，`statuses` 元素变成 `{name, tone, group, short}`。
- 所有 `import { JOB_STATUSES }` 的地方（`Board.jsx` 漏斗/日历/状态弹窗/批量、`Dashboard.jsx`）改用 hook。
- `JOB_STATUSES` 只保留作为「首次默认值 / 老配置无 group 时的推断表」，不再是渲染源。
- `settings/Customize.jsx` 的状态编辑区加两列：`group`（下拉四选一）、`short`（一个字，日历徽标用）。保存时校验：每个 group 至少有一个状态。

### 5.2 全量页漏斗

- 10 列漏斗改为**按 group 分组的两段式**：上行 4 个（未投 / 已投等消息 / 流程中 / 结束），下行为组内细分状态；人数为 0 的档位不显示（现在 8 个 0 挤在同一行）。
- 色条：分组段用 group 汇总，hover 展开细分。
- 增加「新岗」chip（`publish_date` ≤7 天）与「缺日期」提示：`publish_date` 为空的行不计入新岗，并在顶部提示「N 条没填发布时间，无法判断新岗」。

### 5.3 跟进页（`FollowUpView.jsx`）

四块，全部可点进详情：

1. **等回音**：`applied_date` 有值且 group ∈ {applied}，按天数倒序，≥14 天标「可催」；
2. **该做了**：`next_action_date <= today`；
3. **卡住了**：`status_changed_at` 距今 ≥ 14 天且未结束；
4. **逾期没投**：`plan_date < today` 且是 todo 组 —— 提供「全部挪到今天」。

每块右上角「生成待办」→ 批量写 `todos`（`title = 公司 岗位 + 动作`，`due_date = today`，`priority = high`）。

### 5.4 进展时间线

- 排序改为 `event_date` 降序（无日期回落到 `created_at`）。
- 每条支持编辑 / 删除（`PATCH`、`DELETE` `job_events/:id`）。
- `title` / `note` 里的 URL 自动识别成可点链接（`MarkdownLite` 已有链接解析，复用它）。
- 新增事件时可勾「同时把状态推进到 ▾」（下拉）。
- 空 `event_date` 默认填今天（现在允许空，导致时间线排不出顺序）。

### 5.5 简历库

- 顶部加搜索框：匹配 `name / target_role / folder / note`。
- 卡片加「被 N 个岗位引用」，点击 → 跳全量视图并预置 `resume_id` 筛选。
- 分组排序：默认 **按方向**（`folder` 里含「定向版_」的按方向聚），「投递_YYYY-MM-DD」这类按天文件夹收进一个可折叠的「按天归档」区（现在 12 份挤在最前面）。
- `in_use` 保证唯一：设为在用时清其他（已有逻辑），并在读取端兜底——若发现多条 `in_use`，只认 `updated_at` 最新的一条，其余静默忽略，页面上给一条提示「发现 N 份在用，已按最新一份显示」。
- 删除时提示「关联的 N 个岗位会失去简历版本」，并调 3.5 的清理。
- `file_url` 为空的卡片标「仅文本版」，不再显示「打开文件」。

### 5.6 面试复盘

- 公司下拉换成可搜索 combobox，选项文本 `公司 · 岗位`，只列 group ≠ closed 的记录（现在 58 项平铺、14 个「快手」不可区分）。
- 允许 0 题保存为草稿（去掉「至少一道题」硬校验，改为保存后提示「还没记题目」）。
- 「结果 = 通过」时弹一次「把看板状态推进到 ▾」，确认后 `PATCH job_apps.status`（写入 `interviews.status_sync = "1"`）。
- 列表加筛选：公司 / 轮次 / 结果。

### 5.7 首页口径（`Dashboard.jsx`）

- `activeJobs` = 未结束（group ≠ closed）——**口径改名**「在池岗位」。
- `共投递 N 家` → `已投 N · 待投 M · 逾期 K`，其中 `已投` 只数 `applied_date` 有值的。
- 「求职最新进展」卡片按 `updated_at` 降序取 4 条（现在是 `listRows` 默认的 `created_at` 降序，永远显示最早灌进来的那 4 条）。
- 新增统计卡「本包进度 x/y」（当日 `batch_date` 的包）。

### 5.8 日历 / 待办联动

- `Calendar.jsx` 并行拉 `job_apps`，把 `plan_date` 渲染成 terracotta 圆点，`applied_date` 渲染成绿色点；点开当天详情里列出岗位（可跳详情）。
- 「逾期未投」→「生成待办」走 5.3 的同一个函数。

### 5.9 策略体检（`job_policy`）

- `JobForm` 增加 `city`、`company_type`、`source` 三个字段（`city` 从 `location` 自动预填，可改）。
- 本包卡片顶部显示一行体检结果：`中小厂 8 / 大厂 2（上限 2）· 京津 9 · 新岗 4 · 红线命中 0`，超配比时红字 + 具体哪几条是大厂。
- `company` 命中 `blacklist` → 行左侧红条，保存时 `confirm` 二次确认。
- 全量视图增加筛选：城市、公司类型、来源、是否新岗。

### 5.10 周报（`Report.jsx`）

「求职进展」段补三行硬数据：`本期投递 N 家（大厂 a / 中小厂 b）`、`回复率 = 有状态推进 / 已投`、`待跟进 N 家（列出公司名）`。
事件行按 `event_date` 过滤（现在 `inRange(r.event_date)` 对空日期的事件直接丢弃）。

## 6. B3 · 打磨

### 6.1 保存后局部更新（修详情面板不刷新 + 少一次全量拉）

- `JobForm` 保存成功后返回 row；容器用 `setApps(prev => prev.map(x => x.id === row.id ? row : x))` 替换，**不调 `load()`**。
- 若详情面板开着且是同一条 → `setDetail(row)`。现在 `save()` 只关弹窗 + `load()`，`detail` 仍是旧对象，改完名字面板标题还是旧的。
- `changeStatus` / `markApplied` / 事件增删同理，用返回值就地替换。
- `load()` 保留给首次进入和 `useLiveReload`（跨端改动用）。

### 6.2 批量操作改走 bulk 接口

- `bulkApply` / `bulkMarkApplied` 改调 `PATCH /api/data/job_apps/bulk`，一次请求。
- 失败提示要分情况：`400` 显示 `failed_ids` 对应公司名；网络错误提示「可能部分成功，刷新看看」并自动 `load()`。
- 批量浮条增加「移出本包」「改档位」「改城市」三个动作。

### 6.3 移动端

- 列表 `<640px` 不再横向滚动表格：切成两行卡片（公司·岗位 + 状态；城市/计划/档位一行小字），操作按钮 ≥ 36px。
- 「标记已投」按钮触控区加 padding（现在 11px 字 + `px-1.5 py-0.5`，手机上很容易点空）。
- 批量浮条加 `pb-[env(safe-area-inset-bottom)]`，页面底部留 88px 空白，避免遮住最后一行。
- 投递模式在手机上全屏、按钮置底。

### 6.4 批量导入（`BulkImport.jsx`）

- 入口：全量视图右上「批量导入」。
- 支持三种粘贴格式：JSON 数组、CSV（带表头）、Markdown 表格（`投递清单.md` 直接粘）。
- 解析后展示预览表：字段映射 + 逐行校验（缺公司/缺链接/重复链接/城市识别失败），可逐行取消勾选。
- 确认后调 `POST /api/data/job_apps/bulk`，成功后提示「导入 N 条，跳过 M 条（重复）」。
- 再加「从链接导入单个」：粘 URL → 调 `/api/jobs/parse-link` → 预填表单。

### 6.5 性能

- `listRows("job_apps")` 全量拉取在 <500 条时够用，暂不分页；但 `useLiveReload` 增加 500ms debounce，避免批量写时的刷新风暴。
- 频繁读取的 `settings` 在 `colors.js` 里做进程内缓存（一次会话只拉一次）。

## 8. 验收：人工走查 14 步

跑完 B1–B3 后按顺序做一遍，全部通过才算完：

1. 新建一条岗位，`plan_date` 默认今天、`batch` 默认今天的包；保存后立刻出现在「今天」里，不需要刷新。
2. 「今天」页能看到：今日待投 N、逾期 N（带「全部挪到今天」）、今日已投 N。
3. 点逾期那条「标记已投」→ 它留在原位置变成灰色「已投 ✓」，**不从列表消失**；`applied_date` = 今天，`status` 自动前进一档。
4. 手动把状态改回「待投递」→ `applied_date` **不被清空**（保留历史），页面提示「已退回未投状态，投递日期保留」。
5. 进投递模式：链接能开、招呼语能一键复制、简历能打开、「投完了」后自动跳下一条；投完 3 条回「本包」看进度是 3/10。
6. 「本包」页体检行显示配比；往包里加第 3 个大厂时出红字提示超上限。
7. 全量页：点漏斗一档后再点「逾期未投」，两个条件**同时**生效，两个按钮都保持高亮；再点一次各自取消。
8. 设置里把「一面中」改名为「技术面」（`group=progress`）→ 看板所有位置（漏斗、日历、状态弹窗、卡片、首页）都显示「技术面」，没有任何地方显示「待投递」；老数据里还是「一面中」的 2 条显示为「一面中」且不崩。
9. 简历库搜「剪映」能搜到；某份简历点「被 3 个岗位引用」跳到全量并筛出那 3 条；删掉它时提示关联数并确实删掉 uploads 里的文件。
10. 面试复盘：下拉能搜「快手」并看到 14 个不同岗位；不记题目也能存草稿；结果选「通过」后弹出推进状态，确认后看板状态同步。
11. 时间线：补记一条 11-18 的事件，它排到 11-19 那条下面（按事件日期）；能编辑、能删；标题是 URL 的显示成可点链接。
12. 首页显示「已投 4 · 待投 54 · 逾期 10」，不再出现「共投递 58 家」。
13. 日历上 11-25 那天有点，点开能看到那 5 条岗位。
14. 手机（390px）打开：列表不横滚、按钮点得中、投递模式全屏可用。

## 9. 边界与不做的事

- 不做真正的流程引擎（面试轮次自动串联、offer 审批流），这个工具只需「记清楚、看得见」。
- 不做多用户协同/分享看板。
- 不把 `job_apps` 迁移到 SQLite：JSON + 事务够用，改存储的成本远大于收益。
- 不在这一轮做简历内容 diff（`content` 文本对比），只做版本清单与引用关系。
- 不自动爬招聘站（反爬 + 合规风险），只做「粘贴链接 → 解析预填」。

## 10. 部署与回滚

1. 先在 `dev` 分支完成 B0，部署到线上（新字段可空、老前端无感）。
2. 跑 `migrate_jobs_v2.js`（先 dry-run），再部署 B1。
3. B1 上线后观察 3 天，确认「今天 / 本包」的计数与人工核对一致，再上 B2。
4. 回滚：代码回滚用 `git revert`；数据回滚用 `data/backups/` 里迁移前的快照（`db.before-v2.json`）。新字段是增量的，回滚代码不会丢数据。
